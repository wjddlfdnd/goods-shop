# 06. 배포 (10단계)

배포 환경: **Vercel(앱) + Neon(PostgreSQL) + Vercel Blob(이미지)**. 2026-11-26 사용자 결정(LEDGER #113·#114).

## 구조

| 항목 | 내용 |
|---|---|
| 배포 브랜치 | `main`만. PR이 main에 병합되면 Vercel이 자동으로 빌드·배포한다. 다른 브랜치는 건너뛴다(`vercel.json`) |
| 빌드 명령 | `npm run vercel-build` = `prisma migrate deploy` → `prisma/bootstrap.ts`(초기 데이터) → `next build` |
| 초기 데이터 | 상품이 없을 때만 샘플 카테고리 6개 + 미분류 + 상품 15개. 관리자 1명은 `ADMIN_EMAIL`·`ADMIN_PASSWORD` 값으로. 데이터를 지우지 않으므로 빌드마다 실행해도 안전 |
| 이미지 | `BLOB_READ_WRITE_TOKEN`이 있으면 Vercel Blob에 올리고 Blob URL을 DB에 저장. 샘플 상품 이미지는 `public/images/products` |
| 상태 확인 | `GET /api/health` |

## 환경 변수 (Vercel → Project → Settings → Environment Variables, Production)

| 이름 | 넣는 방법 |
|---|---|
| `DATABASE_URL` | Neon 연동이 자동으로 넣음(연결 풀 URL) |
| `DATABASE_URL_UNPOOLED` | Neon 연동이 자동으로 넣음(직접 연결 URL, 마이그레이션용) |
| `BLOB_READ_WRITE_TOKEN` | Blob 저장소를 프로젝트에 연결하면 자동으로 들어감 |
| `ADMIN_EMAIL` | 직접 입력. 배포 관리자 이메일 |
| `ADMIN_PASSWORD` | 직접 입력. 8자 이상. 개발용 `admin1234`는 쓰지 않는다 |

## 처음 배포하는 순서 (사람이 브라우저에서)

1. **Vercel 가입**: vercel.com에서 GitHub 계정으로 로그인(Hobby 무료).
2. **프로젝트 가져오기**: Add New → Project → `wjddlfdnd/goods-shop` Import. 프레임워크는 Next.js로 자동 인식된다. 바로 Deploy를 누르면 환경 변수가 없어 첫 빌드가 실패하는데, 정상이다(아래를 마치고 다시 배포).
3. **DB 연결**: 프로젝트 → Storage → Create Database → **Neon**(Serverless Postgres) → 지역은 앱 함수 지역과 가깝게(한국 사용자라면 아시아·도쿄 또는 서울 근처) → 프로젝트에 연결. `DATABASE_URL`·`DATABASE_URL_UNPOOLED`가 자동으로 생긴다.
4. **이미지 저장소 연결**: Storage → Create → **Blob** → 프로젝트에 연결. `BLOB_READ_WRITE_TOKEN`이 생긴다.
5. **관리자 계정 값**: Settings → Environment Variables에 `ADMIN_EMAIL`, `ADMIN_PASSWORD`를 Production으로 추가.
6. **다시 배포**: Deployments → 최근 배포의 ⋯ → Redeploy. 빌드 로그에 `All migrations have been successfully applied.`와 `bootstrap done { catalog: 'created', admin: 'created', products: 15 }`가 보이면 성공.

## 배포 후 확인 (스모크 테스트)

- [ ] `https://<배포 주소>/api/health`가 `ok`
- [ ] 홈에 신상품·인기 상품·카테고리가 보인다
- [ ] 회원가입 → 로그인 → 장바구니 → 주문 → 주문 완료 → 주문 내역 → 주문 취소
- [ ] `/admin/login`에서 배포 관리자로 로그인 → 대시보드 숫자
- [ ] 관리자 상품 수정에서 이미지 업로드 → 상품 상세에 보인다(Blob URL) → 삭제
- [ ] 휴대폰에서 같은 흐름 한 번

## 운영

- **새 버전 배포**: Git Flow대로 `release-*` → `main` PR 병합 → 자동 배포. 스키마 변경은 마이그레이션 파일만 있으면 빌드가 적용한다.
- **긴급 수정**: `hotfix-<버전>`을 main에서 만들어 main·develop에 병합.
- **롤백**: Vercel Deployments에서 이전 배포를 Promote. 마이그레이션은 되돌리지 않고 새 마이그레이션으로 고친다.
- **관리자 비밀번호 변경**: `ADMIN_PASSWORD`를 바꾸고 Redeploy. 그 관리자의 기존 로그인은 모두 끊긴다.
- **무료 구간 한도**: Vercel Hobby·Neon Free·Blob 무료 용량 안에서 연습용으로 쓴다. 한도는 각 서비스 요금 페이지 기준.
