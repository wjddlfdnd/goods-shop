## 점검 방법

1. **자동 테스트**: `npm test`(정책), `npm run test:e2e`(핵심 흐름), CI(GitHub Actions)에서 PR마다 실행.
2. **화면 크롤**: 비회원·회원·관리자로 40개 화면을 390px·1280px로 열어 콘솔 오류, 가로 넘침, axe 접근성, 24px 미만 터치 영역을 수집.
3. **경계 사례 탐색**: 동시 담기, 소수·문자·음수 수량, 깨진 JSON, 주문서 이상한 주소(0·음수·문자·초과 수량·남의 항목), 금액 조작 요청, 긴 입력, 만료 세션, 대소문자 이메일, 검색 특수문자, 태블릿 폭.
4. **화면 확인**: 모바일·데스크톱 캡처를 하이파이 시안과 비교.

## 마이그레이션 사고 기록
QA-05 마이그레이션을 개발 DB에 처음 적용할 때, 경계 사례 점검으로 넣은 긴 값 때문에 중간에 실패했고 PostgreSQL에 일부만 적용됐다(외래 키만 삭제된 상태). 데이터를 지우지 않고 길이를 넘는 값 2건을 잘라낸 뒤 같은 SQL을 한 트랜잭션으로 마저 적용해 복구했다. 이후 마이그레이션 파일 자체를 `BEGIN … COMMIT`으로 감싸 부분 적용이 생기지 않게 했다.

# 2차 QA (release-1.1.0, 2026-11-26)

범위: 2차 기능 U-03 내 정보 수정, U-04 배송지 관리, U-05 주문 내역, U-06 찜, O-07 주문 취소, A-01 관리자 로그인, A-06–A-08 주문 관리·상태 변경·대시보드. 1차 기능은 회귀만 확인.

## 점검 방법

1. **자동 테스트**: `npm test` 48개, `npm run test:e2e` 15개(데스크톱·모바일). 모두 통과.
2. **화면 크롤**: 비회원·회원·관리자로 49개 화면을 390·768·1280px에서 열어 콘솔 오류, 가로 넘침, axe 접근성, 24px 미만 터치 영역을 확인. 수정 후 결과는 오류 0, 넘침 0, axe 위반 0, 작은 터치 영역 0.
3. **경계 사례 탐색(API·화면 31개 항목)**: 다른 회원의 배송지와 주문, 회원이 관리자 기능을 쓰는 경우, 상태 건너뛰기, 관리자 상태 변경과 회원 취소의 동시 요청, 기본 배송지 동시 지정, 같은 이름·이메일 동시 생성, 없는 날짜·범위 밖 페이지, 판매 현황 숫자와 DB 비교, 관리자 로그인 세션. 수정 후 전 항목 통과.
4. **화면 확인**: 2차 모바일 화면(배송지·주문 내역·주문 상세·찜 목록)을 캡처해 1차 화면 패턴과 비교. 이상 없음.
