## 잘된 점

- **문서 우선순위와 장부**: PRD > 기능 명세서 > DESIGN > 시안 순서를 정하고, 개발 중 정한 가정·불일치를 모두 장부(LEDGER)에 남겨 문서에 반영했다. 코드와 문서가 어긋난 채로 쌓이지 않았다.
- **정책을 테스트로 고정**: 재고 조건부 차감, 주문 멱등성, 결제 완료일 때만 취소, 상태 순서 같은 PRD 규칙을 lib 함수 단위 테스트로 만들어, 이후 수정이 규칙을 깨면 바로 드러났다.
- **동시성까지 확인**: 동시 결제, 같은 요청 키 동시 주문, 관리자 상태 변경과 회원 취소의 동시 요청, 기본 배송지 동시 지정까지 실제로 동시에 요청해 보며 찾고 고쳤다.
- **CI가 실제로 막아 줌**: 2차 QA 수정에서 생긴 관리자 로그인 입력 유실(스트리밍 교체 경쟁)은 로컬에서는 통과하고 CI에서만 실패했다. CI가 실패한 PR은 병합하지 않는다는 규칙 덕분에 main에 들어가지 않았다.
- **QA를 단계마다**: 2차 개발 전에 1차 QA를 먼저 마치고 v1.0.0을 만든 덕분에 2차 버그와 1차 버그가 섞이지 않았다.
